# CipherCompiler Architecture

**Compiler:** CipherCompiler
**Language:** Arc
**Version:** 1.0

---

## 1. Overview

CipherCompiler is a compiler for the Arc programming language.

The compiler translates Arc source code into x86-64 assembly code, which can then be assembled and linked into an executable program.

The overall architecture is:

```text
                    Arc Source Code
                          │
                          ▼
                   ┌─────────────┐
                   │    Lexer    │
                   └──────┬──────┘
                          │
                        Tokens
                          │
                          ▼
                   ┌─────────────┐
                   │    Parser   │
                   └──────┬──────┘
                          │
                          ▼
                   ┌─────────────┐
                   │     AST     │
                   └──────┬──────┘
                          │
                          ▼
                ┌────────────────────┐
                │ Semantic Analysis  │
                └─────────┬──────────┘
                          │
                    Validated AST
                          │
                          ▼
                   ┌─────────────┐
                   │  Code Gen   │
                   └──────┬──────┘
                          │
                          ▼
                  x86-64 Assembly
                          │
                          ▼
                  Assembler / Linker
                          │
                          ▼
                     Executable
```

# 2. Compiler Phases

1. Lexical Analysis
2. Syntax Analysis
3. Abstract Syntax Tree Construction
4. Semantic Analysis
5. Code Generation

# 4. Lexical Analysis

The lexer is the first stage of CipherCompiler.

Its responsibility is to convert the raw Arc source code into a sequence of tokens.

For example:

```arc
int x = 10 + 20;
```

is converted into:

```text
INT
IDENTIFIER(x)
ASSIGN
INTEGER(10)
PLUS
INTEGER(20)
SEMICOLON
EOF
```

The lexer is implemented by:

```text
src/lexer/Lexer.java
```

Token information is represented by:

```text
src/lexer/Token.java
```

The set of supported token types is defined in:

```text
src/lexer/TokenType.java
```

### Responsibilities

The lexer handles:

* keywords
* identifiers
* integer literals
* decimal literals
* character literals
* string literals
* operators
* delimiters
* comments
* whitespace
* source locations
* lexical errors

The lexer does not determine whether a sequence of tokens forms a valid program. That is the parser's responsibility.

---

# 5. Syntax Analysis

The parser receives the token sequence generated by the lexer.

Its purpose is to determine whether the tokens follow the grammar of Arc.

Example:

```arc
int x = 10 + 20;
```

The parser recognizes:

```text
Variable Declaration
    │
    ├── Type: int
    ├── Name: x
    └── Initializer
          │
          └── Binary Expression
                ├── 10
                ├── +
                └── 20
```

CipherCompiler uses a **recursive-descent parser**.

The parser implementation is:

```text
src/parser/Parser.java
```

The parser follows the grammar defined in:

```text
docs/grammar.md
```

---

# 6. Abstract Syntax Tree

The parser constructs an Abstract Syntax Tree (AST).

The AST represents the logical structure of the program rather than its exact source-code formatting.

For:

```arc
int result = 2 + 3 * 4;
```

the AST is conceptually:

```text
VariableDeclaration
│
├── Type: int
├── Name: result
└── Initializer
      │
      └── BinaryExpression(+)
            ├── Literal(2)
            └── BinaryExpression(*)
                  ├── Literal(3)
                  └── Literal(4)
```

The tree correctly represents operator precedence:

```text
2 + (3 * 4)
```

rather than:

```text
(2 + 3) * 4
```

---

# 7. AST Organization

The AST is divided into expressions and statements.

```text
ASTNode
├── Expression
│   ├── BinaryExpression
│   ├── UnaryExpression
│   ├── LiteralExpression
│   ├── VariableExpression
│   └── CallExpression
│
└── Statement
    ├── VariableDeclaration
    ├── Assignment
    ├── ReturnStatement
    ├── IfStatement
    ├── WhileStatement
    └── ExpressionStatement
```

The root of an Arc program is represented by:

```text
Program
```

# 8. Semantic Analysis

Syntax alone is not enough to determine whether a program is valid.

For example:

```arc
int x = 10;

x = "hello";
```

The syntax is valid, but the assignment is invalid because the types do not match.

Semantic analysis checks the meaning of the program after parsing.

The main semantic analyzer is:

```text
src/semantic/SemanticAnalyzer.java
```

---

# 9. Symbol Table

The symbol table stores information about identifiers.

Example:

```text
Name       Type       Scope
---------------------------
x          int        main
age        int        main
name       string     main
```

The symbol table is implemented by:

```text
src/semantic/SymbolTable.java
```

Each symbol is represented by:

```text
src/semantic/Symbol.java
```

---

# 10. Semantic Checks

CipherCompiler performs checks including:

### Variable declaration

```arc
int x = 10;
```

### Duplicate declaration

```arc
int x = 10;
int x = 20;
```

This should produce an error when duplicate declarations are not allowed in the same scope.

### Undeclared variable

```arc
x = 10;
```

when `x` has not been declared.

### Type compatibility

```arc
int x = "hello";
```

### Function existence

```arc
int x = calculate(10);
```

when `calculate` does not exist.

### Function argument checking

The number and types of arguments must match the function parameters.

### Return type checking

```arc
func int add(int a, int b) {
    send "hello";
}
```

must produce a type error.

### Loop control

`break` and `skip` are only valid inside loops.

# 11. Scope Management

Arc uses lexical block scope.

Example:

```arc
func int main() {

    int x = 10;

    if (x > 5) {

        int y = 20;

        output(y);
    }

    // y is not accessible here

    send x;
}
```

The semantic analyzer maintains nested scopes.

Conceptually:

```text
Global Scope
│
└── main Scope
    │
    └── if Scope
        └── y
```

When the compiler leaves a block, the corresponding scope is removed.

---

# 12. Code Generation

After semantic analysis succeeds, the validated AST is passed to the code generator.

The code generator converts the AST into x86-64 assembly.

Implementation:

```text
src/codegen/CodeGenerator.java
```

The initial code generator will target a standard x86-64 environment.

Example Arc code:

```arc
func int main() {
    send 42;
}
```

will conceptually produce assembly equivalent to:

```asm
main:
    mov eax, 42
    ret
```

The exact generated assembly depends on the implementation of CipherCompiler.

---

# 13. Expression Code Generation

For:

```arc
send 2 + 3;
```

the compiler builds:

```text
BinaryExpression(+)
├── 2
└── 3
```

The code generator recursively evaluates the operands and generates the corresponding assembly instructions.

Conceptually:

```asm
mov eax, 2
push rax

mov eax, 3
pop rcx

add eax, ecx
```

The final value is then returned.

---

# 14. Control Flow Generation

Conditional statements require labels and jumps.

For:

```arc
if (x > 10) {
    send x;
} else {
    send 0;
}
```

the generated assembly will conceptually contain:

```text
evaluate condition

jump to ELSE if condition is false

THEN:
    ...
    jump to END

ELSE:
    ...

END:
```

Loops use the same concept.

For:

```arc
loop (x < 10) {
    x = x + 1;
}
```

the compiler generates a loop structure containing:

```text
LOOP_START:
    evaluate condition

    jump to LOOP_END if false

    body

    jump to LOOP_START

LOOP_END:
```

---

# 15. Function Code Generation

Functions are compiled into separate assembly labels.

Example:

```arc
func int add(int a, int b) {
    send a + b;
}
```

Conceptually becomes:

```asm
add:
    ...
    ret
```

Function calls are translated according to the target platform's calling convention.

# 16. Compiler Driver

`Main.java` acts as the entry point of CipherCompiler.

Its responsibility is to coordinate the compiler pipeline:

```text
Read Arc source
      ↓
Create Lexer
      ↓
Tokenize source
      ↓
Create Parser
      ↓
Build AST
      ↓
Run Semantic Analyzer
      ↓
Generate Assembly
      ↓
Write assembly file
```

Conceptually:

```text
Main
 │
 ├── Lexer
 │
 ├── Parser
 │
 ├── AST
 │
 ├── SemanticAnalyzer
 │
 └── CodeGenerator
```

# 17. Error Handling

CipherCompiler should provide errors with source locations.

Example:

```text

int x = "hello";
        ^

Cannot assign value of type string to variable of type int.
```

Errors are categorized as:

```text
Lexical Error
Syntax Error
Semantic Error
Code Generation Error
```

# 19. Example Compilation Pipeline

Consider:

```arc
func int main() {

    int x = 10;
    int y = 20;

    if (x < y) {
        send x + y;
    }

    send 0;
}
```

### Step 1 — Lexical Analysis

The source becomes tokens:

```text
FUNC
INT
IDENTIFIER(main)
LEFT_PAREN
RIGHT_PAREN
LEFT_BRACE
INT
IDENTIFIER(x)
ASSIGN
INTEGER(10)
...
```

### Step 2 — Parsing

Tokens are converted into an AST.

```text
Program
└── Function(main)
    └── Block
        ├── VariableDeclaration(x)
        ├── VariableDeclaration(y)
        ├── IfStatement
        │   └── BinaryExpression(<)
        │       ├── x
        │       └── y
        └── ReturnStatement
```

### Step 3 — Semantic Analysis

The compiler verifies:

```text
x → int
y → int

x < y → truth

x + y → int

send x + y → valid for int main()
```

### Step 4 — Code Generation

The validated AST is converted into x86-64 assembly.

### Step 5 — Assembly and Linking

The generated assembly is passed to the system toolchain to produce an executable.
